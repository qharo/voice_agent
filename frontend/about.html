Voice Agent

About

This is an implementation of a real-time voice assistant. Your speech is transcribed live, reasoned with a language model and responded to with a natural voice. It can also answer questions about PDFs you upload, and reach live tools for weather, currency conversion, and more.

Pipeline Agent
  1. Turn input — the transcript, plus the last 20 messages, the active system prompt (custom, preset, or default), and an “a PDF is uploaded” note when a document is loaded.
  2. LLM call with tool_choice = auto (Groq gpt-oss-20b).
  3. Decision: did the model emit tool calls?
  4. Execute the chosen tool and append its result, then loop back to B — at most five iterations per turn, otherwise a fallback reply.
  5. Final answer text — no more tool calls.
  6. Speak the reply: strip_markdown, then Piper TTS.
  7. Tool picker: 7 free, keyless tools — weather, calculator, Wikipedia, dictionary, exchange rate, world time, document search.
  8. Document search (RAG): PDF ≤ 10 pages / 20 MB → 1000-char chunks with 150 overlap → bge-small-en-v1.5 embeddings → top-4 by cosine.
Delivery
  • A push to main triggers GitHub Actions (.github/workflows/deploy.yml). dorny/paths-filter looks at what changed and builds only the affected part — backend, frontend, or the Helm chart.
  • Backend and frontend build as linux/amd64 Docker images and are pushed to GHCR (ghcr.io/qharo/voice-agent-*), using the Actions layer cache to keep rebuilds fast.
  • The deploy job loads a kubeconfig from a secret, runs helm upgrade when the chart changed, otherwise kubectl rollout restart for just the changed Deployment, then waits on rollout status.
  • The cluster is K3s. The Helm chart helm/voice-agent carries the namespace, both Deployments and Services, and an ingress-nginx Ingress with cert-manager (Let’s Encrypt) TLS at qharo-voice-agent.duckdns.org, WebSocket-friendly timeouts, and a 20 MB upload cap.
  • The GROQ_API_KEY ships in the repo as a Bitnami SealedSecret — encrypted, safe to commit, decryptable only in-cluster.
  • The backend exposes Prometheus metrics at /metrics; a ServiceMonitor scrapes them every 15 seconds and a Grafana dashboard ships as a ConfigMap — active sessions, queue depth, STT / LLM / TTS latencies, tool calls, and error counts.

Notes

Design tradeoffs

  • Push-to-talk instead of voice-activity endpointing — you decide when a turn ends, which keeps the interaction predictable and the server simple.
  • The LLM is hosted (Groq) for speed and quality, but STT and TTS run locally in the backend process — no per-request cost, no extra network hop, and they work offline.
  • Concurrency is capped at four turns so a small box stays responsive; extra callers wait in a fair queue rather than degrading everyone.
  • RAG holds one document at a time, and the prompt / preset / document state is process-global rather than per-session — deliberately minimal for a single-user demo.

Known limitations

  • The LLM response isn’t streamed into TTS yet — the full reply is generated first, then synthesised. STT already emits partial transcripts, but the live turn still waits for the final text.
  • The RAG index lives in memory, so an uploaded document is lost on a backend restart or redeploy.
  • Single backend replica — the in-process models and in-memory state don’t share across pods.
  • Voices are English-only.

Future work

  • Feed partial STT hypotheses straight into the turn so generation can start before you finish speaking.
  • Stream LLM tokens into TTS sentence-by-sentence to cut time-to-first-audio.
  • Per-session prompt and document state; multi-document RAG.
  • Horizontal autoscaling with shared state pulled out of the process.

Credits & links

The models and tools are all free and keyless: Moonshine (STT), Piper (TTS), gpt-oss-20b served by Groq, and open APIs for weather (Open-Meteo), currency (Frankfurter), Wikipedia, dictionary, and world time.
