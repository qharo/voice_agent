Architecture

One websocket, four stages, zero gluing.

Every turn flows through the same pipeline. The browser holds one live connection; the backend streams each stage into the next.

How it works

A turn, from the ground up

Conversational, but exact.

1

Capture

Hold space. The browser grabs 16 kHz mono audio from the mic and ships it over a single websocket as raw PCM — no upload-and-wait, no files. Release to send.

2

Speech to text

Moonshine streaming (tiny) runs on the box — a quantised GGUF model loaded once and kept in memory. It emits partial transcriptions every 200 ms, so you see your words appear as you say them.

3

Think with tools

qwen 3.6-27b on Groq turns your words into intent. When a question needs real data it emits a tool call; the tool runs locally, its result feeds back in, and generation continues — up to five rounds for things like weather then a currency conversion.

4

Text to speech

Piper synthesises the whole answer as one streaming pass and emits raw PCM in 8 KB chunks. Markdown and formatting are stripped server-side first, so only clean plain text ever reaches the voice.

5

Stream back

The browser schedules audio chunks back-to-back on a low-latency Web Audio clock for gapless speech — the green screen flips to black the moment it starts talking. Pressing space mid-answer triggers barge-in to cut in instantly.

Tools

Six tools. All free, none need a key.

The LLM picks a tool from JSON schemas the backend advertises. Each tool is a schema + execute() pair, auto-discovered at startup.

Performance

Measured, not promised.

Every stage records a Prometheus histogram; Grafana plots p50 / p95 / p99 per stage and end to end.

Drop your dashboard screenshot at assets/grafana.png to show it here
Fifteen metrics are exported from backend/metrics.py — request counts, per-tool latency, queue depth, active sessions, and stage timings — exposed on /metrics and scraped by a Prometheus ServiceMonitor.
Infrastructure

Wired the way production is wired.

TLS to telemetry, from cert to dashboard — all declared as code.

🔐

End-to-end TLS

cert-manager mints Let's Encrypt certs for qharo-voice-agent.duckdns.org; ingress-nginx terminates with the ACME http01 solver and long websocket timeouts.

🗝️

Sealed Secrets

The Groq API key lives encrypted in the repo as a SealedSecret. It decrypts only inside the cluster — safe to commit, never in plaintext.

🚀

CI/CD on push

GitHub Actions builds both images with BuildKit, caches to GHCR, then runs helm upgrade and a rolling restart straight from the workflow.

📈

Prometheus + Grafana

A ServiceMonitor scrapes /metrics; a versioned Grafana dashboard ships as a ConfigMap from the Helm chart — dashboard lives with the app.

🚦

Fair-queue sessions

Counter caps concurrency at 4. New joins are queued and told their position ([QUEUE:pos]) so nobody talks into the void.

Decisions

Trade-offs I actually weighed.

Piper over Pocket TTS

This box is CPU-bound and answers must start fast. Piper streams raw PCM straight from a subprocess with end-of-speech on pipe EOF, hitting time-to-first-audio in the low hundreds of milliseconds. Pocket (an ONNX INT8 model) is built in and sounds great, but its frame-by-frame generation couldn't hit the same real-time budget on shared CPU — so Piper is the default.

K3s over Docker Compose

Compose is fine for one machine, but this became a deployment story. K3s brings a real scheduler: liveness and readiness probes route traffic to healthy pods, updates roll without downtime, and the Helm chart lets the whole stack — ingress, certs, secrets, dashboards — live in version control and redeploy on push.
